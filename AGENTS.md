# realtime-voice-harness

Text-in/text-out test harness for realtime voice apps with agentic harnesses. A test "speaks" by synthesizing text to audio, pipes it into the app under test, records the audio reply, and transcribes it back to text for assertions — no microphone, keys, or network required for the loop itself.

## Stack

- Runtime: bun 1.4.4 (Node 22+ also works for node:test)
- Package manager: bun
- TypeScript 5.9 + tsgo (`@typescript/native-preview`, native TS 7 preview)

## Commands

- Install: `bun install`
- Build: `bun run build` (emits `dist/esm` + `dist/cjs` with declarations)
- Unit tests: `bun run test` (vitest, `tests/` only)
- All framework/agent suites: `bun run test:examples` (builds first, then bun, node, jest, Playwright, LangChain, OpenAI-Realtime, midscene)
- Per-suite: `bun run test:bun|test:node|test:jest|test:playwright|test:langchain|test:tanstack|test:openai-realtime|test:midscene`
- Lint: `bun run lint` (eslint, zero warnings)
- Typecheck: `bun run typecheck` (`tsgo --noEmit` on `src/`+`tests/` and on `tsconfig.examples.json`)

## Layout

```text
src/
  audio/         PCM audio value objects
  speech/        synthesizer/transcriber driver contracts
  transport/     realtime transport contract (IRealtimeTransport)
  transports/    concrete transports (AG-UI SSE, LangChain, OpenAI Realtime)
  harness/       scripted conversation driver
  fakes/         in-memory doubles (no keys, mic, or network)
tests/           unit + transport tests (vitest; relative imports into src)
examples/        per-framework suites importing 'realtime-voice-harness' by name
docs/            getting-started, frameworks, transports, roadmap
scripts/         build helpers (CJS package marker)
```

- `src/index.ts` — public API; import from here, never from internals.
- `src/fakes/` — test doubles only; production adapters implement the same interfaces.
- `vitest.config.ts` scopes unit runs to `tests/`; `vitest.examples.config.ts`
  scopes agent-example runs to `examples/{langchain,openai-realtime}/`.
- Examples self-link: `node_modules/realtime-voice-harness -> ..`, so every
  example imports the built package by name like an external consumer.

## Conventions

- Microsoft style: `PascalCase` classes/interfaces, `camelCase` members, `UPPER_SNAKE_CASE` constants; explicit return types; `private` fields with public accessors only when needed; `readonly` where values never change.
- `interface` for object shapes, `type` for unions; never `any` — use `unknown` with narrowing.
- Every file starts with a `/** @file ... */` header doc comment.
- Constructor injection for all I/O boundaries (synth/transcribe/transport are interfaces).
- `require-await` is off for `*.test.ts`/`*.spec.ts` (async test callbacks are idiomatic); it stays on for `src/`.

## Verification

`bun run typecheck && bun run lint && bun run test && bun run test:examples`
must all pass before a change counts as done. `bun run build` must emit both
`dist/` trees cleanly before a release.

When adding an `examples/<name>/` dir: add a `test:<name>` script, append it
to `test:examples`, add the dir to `allowDefaultProject` in `eslint.config.js`
(one-level globs only), and record the result in the README matrix.

## Do not

- Hand-edit `dist/` (generated by `bun run build`).
- Commit `.env` (see `.env.example` if secrets are ever needed).
- Run networked/live-keyed suites as proof: midscene-live and any real-provider
  check stay out of the default battery; mock-socket tests are the durable proof.
